# Contributing

This is development version 0.1.0 from Lofrano Tecnologia. Keep changes small, original and reviewable. Use synthetic fixtures only; do not include private client code, personal data, credentials or copied implementations.

## Local checks

Use SDK 10.0.403 or a compatible patch selected by `global.json`. From the repository root:

```sh
sh scripts/check.sh restore
dotnet test --solution BoundedObservedSet.sln --no-restore --configuration Release
dotnet run --project demo/BoundedObservedSet.Demo.csproj --no-restore --configuration Release -- --self-test
```

The committed project lockfiles were generated by NuGet. Restore verifies them in locked mode and caches dependencies under `build/packages`. For an intentional dependency update, run `dotnet restore BoundedObservedSet.sln --force-evaluate`, review all generated lock changes, then repeat locked restoration and checks. `sh scripts/check.sh offline` repeats checks without restore. No external service is needed after dependency preparation.

Compiler nullability, current SDK analyzers and warnings-as-errors are enabled. All generated build and package artifacts belong under ignored `build/`; source metadata and lockfiles remain beside their projects.

## Review expectations

- Add a regression showing externally observable behavior, including unchanged canonical bytes for failures.
- Extend the independent event-history oracle when changing causal behavior; do not replace it with calls to the production merger.
- Preserve observed-only removal, fresh dots on every add, historical distinct-element accounting, and validation before commit.
- Consider malicious Unicode, decoded duplicate fields, escaping expansion and integer overflow.
- Do not add clocks, telemetry, transport, history pruning or identity-fencing claims to this core.
- Keep English and Portuguese explanations aligned. Update the contract and unreleased changelog when behavior changes.
- Describe what was actually checked; do not claim unrun tests, benchmarks, deployment, adoption or broad compliance.

Use repository issues and pull requests for ordinary discussion. For vulnerabilities follow [SECURITY.md](SECURITY.md), not a public issue. General contact is through https://lofranotecnologia.com.br.
