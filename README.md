# Bounded Observed Set

Development version **0.1.0**. An original, in-memory C# observed-remove set from [Lofrano Tecnologia](https://lofranotecnologia.com.br), for small offline replica experiments. [Português](README.pt-BR.md).

An element is visible when at least one of its add dots is live. Removal marks only locally observed live dots. An unknown concurrent add survives. There are no clocks, transport, history pruning, or exactly-once promises.

## Install, test, demo

Install the .NET SDK **10.0.403** from the [official .NET site](https://dotnet.microsoft.com/download/dotnet/10.0). `global.json` allows newer patches in the same SDK feature band. Run from the repository root:

```sh
sh scripts/check.sh restore
dotnet test --solution BoundedObservedSet.sln --no-restore --configuration Release
dotnet run --project demo/BoundedObservedSet.Demo.csproj --no-restore --configuration Release -- --self-test
```

The repository includes NuGet lockfiles generated by a real restore. Preparation downloads their exact packages into `build/packages` and runs in locked mode; a dependency/lock mismatch fails rather than updating the locks. Tests and demos then use existing assets without package restoration. For repeat checks use `sh scripts/check.sh offline`. Maintainers changing dependencies must deliberately run `dotnet restore BoundedObservedSet.sln --force-evaluate`, review the generated lock changes, and rerun locked checks.

The library and demo have no third-party runtime package dependencies. Test dependencies are exact xUnit v3 4.0.2, its VSTest adapter 4.0.1 and Microsoft.NET.Test.Sdk 18.11.0. The executable test project uses native Microsoft.Testing.Platform, selected in `global.json`, with the .NET 10 `dotnet test --solution` command.

Example demo output, excluding SDK build messages:

```text
Bounded Observed Set - development 0.1.0
Observed blue/red were removed; unobserved A:3 survives.
Converged: A, B, C; visible: [blue]
{"version":"0.1.0","replicas":3,"converged":true,"visible":["blue"],"historicalDots":3}
```

Assertions always run, including without `--self-test`. Add `--json` for only the JSON application output; add `--no-build` after a successful build to suppress build work. Exit codes: 0 agreement, 1 failed assertion or output I/O error, 2 unsupported argument. The demo is deterministic, synthetic and offline.

## Small API example

Reference `src/BoundedObservedSet.csproj` from a .NET 10 project:

```csharp
using Lofrano.BoundedObservedSet;

string[] members = { "A", "B" };
var a = new ObservedSet("A", members);
var b = new ObservedSet("B", members);
a.Add("blue");                  // A:1
b.Merge(a);                     // B has observed A:1
b.RemoveObserved("blue");       // removes A:1 only
a.Add("blue");                  // A:2, not observed by B
a.Merge(b);                     // blue is still visible via A:2
bool visible = a.Contains("blue");
byte[] snapshot = a.ExportSnapshot();
```

Check every mutating operation's `OperationResult.Code`; the example omits branching for readability. Every successful add allocates a dot, even for a visible element. `GetVisibleElements()` returns a detached ordinal-sorted array. Export returns detached canonical UTF-8 bytes. A receiver chooses its writer explicitly at construction:

```csharp
var restored = new ObservedSet("A", new[] { "A", "B" });
OperationResult result = restored.ImportSnapshot(snapshot);
if (!result.IsSuccess)
    throw new InvalidOperationException(result.Code.ToString());
```

Import replaces state; it is not a merge and is not rollback protection. Only use writer A here if the previous authoritative A writer has stopped and the state has not rolled back. Parallel copies in tests are separate hypothetical experiments, not safe deployed identity cloning.

## Contract at a glance

- Fixed membership: 1–16 distinct IDs, each 1–32 ASCII letters, digits, `_` or `-`, case-sensitive.
- Signed 64-bit causal counters: stored counters 0 through `long.MaxValue`, dots strictly positive. Every add uses a checked increment.
- Well-formed Unicode strings, including empty strings and controls, at most 128 UTF-8 bytes. No normalization or case folding.
- Defaults and hard ceilings: 4,096 historical dots and 1,024 **historical** distinct elements. Lower per-instance caps are supported. Removed facts consume both budgets.
- Merge unions facts, ORs removal flags and takes maximum counters. Conflicting dot ownership, incompatible membership and cap exhaustion reject atomically.
- Schema 1 snapshots contain no local writer, limits, timestamps or credentials. Maximum input is 4,194,304 bytes; duplicate decoded fields, unknown fields and malformed counters are rejected.
- Instance methods use an internal lock. Cross-instance merge captures the source before locking the receiver; it is not a distributed atomic transaction.

See [the precise contract](docs/contract.md) and [design and references](docs/design.md). Diagnostics are fixed result codes, never parser exception text or echoed input.

## Rationale and limits

Keeping removal evidence makes causal behavior inspectable. Refusing an entire oversized merge is preferable here to silently forgetting tombstones and resurrecting old additions. Canonical bytes expose accepted-state convergence without hashes replacing evidence. Algebraic laws apply only when all required merges are accepted within caps and dots have consistent ownership.

History eventually fills. This development version deliberately has no safe compaction, dynamic membership, identity fencing, authentication, confidentiality, network protocol or persistence layer. A snapshot is untrusted data, not proof of authorization. One authoritative writer per replica ID is an external requirement. Counters alone cannot repair cloned identities or rollback. No broad CRDT, JSON canonicalization or security-standard compliance is claimed.

Regression tests include all six orders of three fixed histories, accepted-join laws, atomic failures, maximal escaping, parallel calls, and an independent event-history oracle enumerating 4,096 tiny histories. These are correctness checks, not performance benchmarks or a production-readiness claim.
